# PRD - Autenticazione, Autorizzazione, JWT e CORS

## 1. Obiettivo

Completare l'implementazione di autenticazione e autorizzazione nell'applicazione ASP.NET Core MVC `DashBoard01`, usando ASP.NET Core Identity per gli account applicativi, JWT per token API, CORS centralizzato e pagine Razor/Tailwind per registrazione, login e logout.

## 2. Contesto e Problema

L'applicazione espone dashboard ordini, clienti, prodotti e categorie con dati persistiti su SQL Server tramite EF Core. Il database contiene gia le tabelle ASP.NET Identity, ma il runtime MVC non registra Identity, non autentica gli utenti e non gestisce token JWT o CORS in modo strutturato.

Serve introdurre un flusso completo, verificabile e mantenibile senza salvare segreti reali in file versionati e senza riportare logica applicativa in `Program.cs`.

## 3. Scope

Sono inclusi:

- Pacchetti necessari per ASP.NET Core Identity, EF Core Identity e autenticazione JWT.
- Entity utente applicativa basata su Identity.
- Model e DTO per registrazione, login e logout.
- Registrazione con controlli di validazione e blocco su utente/email esistente.
- Login con cookie MVC e generazione token JWT.
- Logout con rimozione cookie e DTO di risposta.
- Pagine MVC per login, logout e registrazione usando Tailwind.
- Pulsanti login/logout/registrazione nella barra superiore della dashboard.
- Toast Tailwind per operazioni riuscite o errori.
- Gestione errori centralizzata per eccezioni e risultati utente.
- Estensioni dedicate per Identity, JWT e CORS fuori da `Program.cs`.
- Test automatici pertinenti per servizio auth e controller.

## 4. Out of Scope

Sono esclusi:

- Provider esterni OAuth/OpenID Connect.
- Conferma email, recupero password, MFA e lockout avanzato.
- Ruoli amministrativi o policy complesse oltre all'autenticazione base.
- Migrazione completa dello schema Identity se le tabelle esistenti sono gia compatibili.
- Uso di AutoMapper, salvo necessita reale e licenza gratuita verificata; in questo perimetro il mapping manuale e sufficiente.

## 5. Requisiti Funzionali

- L'utente puo registrarsi con nome, cognome, email, data di nascita, citta, paese, codice fiscale, password e ripetizione password.
- La registrazione fallisce se email/login sono gia associati a un utente esistente.
- La registrazione valida campi obbligatori, email, data di nascita, password e conferma password.
- L'utente puo eseguire login usando email nel campo `Login` e password.
- Il login crea una sessione cookie MVC e produce anche un token JWT nel DTO di risposta del servizio.
- L'utente puo eseguire logout dalla pagina dedicata o dalla barra superiore.
- La barra superiore mostra `Logout` quando l'utente e autenticato; mostra `Login` e `Registrati` quando non e autenticato.
- Operazioni riuscite o fallite mostrano toast Tailwind.
- Le pagine dashboard restano navigabili e coerenti su desktop e mobile.

## 6. Requisiti Tecnici

- Usare .NET 9 e lo stile MVC esistente.
- Estendere `DashboardOrdersDbContext` con Identity mantenendo le entity applicative esistenti.
- Usare `IdentityUser` custom per i dati profilo richiesti.
- Spostare configurazione Identity, JWT e CORS in `Extensions/Auth`.
- Mantenere `Program.cs` leggibile e limitato all'orchestrazione host/pipeline.
- Leggere `Jwt` e `Cors` da configurazione, con default sicuri per sviluppo e senza segreti reali in `appsettings*.json`.
- Usare antiforgery sui form MVC POST.
- Non introdurre AutoMapper per mapping semplici.
- Centralizzare messaggi utente e gestione eccezioni senza esporre dettagli sensibili.

## 7. Acceptance Criteria

- `dotnet build DashBoard01.sln` passa.
- `dotnet test DashBoard01.sln` passa.
- `npm run build:css` passa se vengono toccate view o classi Tailwind.
- `Program.cs` delega Identity, JWT e CORS a metodi di estensione in `Extensions/Auth`.
- Registrazione, login e logout sono disponibili da controller e view MVC.
- Il layout mostra i pulsanti corretti in base a `User.Identity.IsAuthenticated`.
- Toast di successo/errore sono renderizzati tramite messaggi temporanei centralizzati.
- I test coprono almeno casi OK, errore e input nulli/non validi del flusso auth.
- Nessun segreto reale e introdotto in `appsettings.json`, `appsettings.Development.json` o `launchSettings.json`.

## 8. Rischi

- Le tabelle Identity esistenti potrebbero non essere allineate ai campi profilo richiesti; potrebbe servire uno script SQL idempotente.
- La chiave JWT non deve essere reale nei file versionati; in sviluppo serve fallback documentato o configurazione locale.
- L'integrazione cookie + JWT richiede ordine corretto di middleware: CORS, autenticazione, autorizzazione.
- Le view auth devono restare coerenti con il layout Tailwind esistente senza introdurre nuove librerie UI.

## 9. Definition of Done

Il lavoro e completato quando pianificazione, implementazione, test, build, compilazione CSS e smoke test locale confermano registrazione, login, stato navbar, toast, logout, configurazione CORS/JWT centralizzata e assenza di segreti versionati.
